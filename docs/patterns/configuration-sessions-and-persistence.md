### System clipboard pattern

`src/clipboard.zig` handles OS clipboard reading/writing via terminal OSC 52 sequences (`\x1b]52;c;<base64>\x07`) with OS-native execution fallback (`wl-copy`/`xclip`/`pbcopy`/`powershell` via `bash.zig`). `clipboard_helper.zig` routes clipboard data dynamically to focused input fields and transcript message blocks.

### Settings lifecycle pattern

`src/tui/settings_lifecycle.zig` manages pending tabbed form edits, syncs values to `app.cached_config` in real-time, and serializes user settings on `Ctrl+S`. `saveSettings` writes only settings-managed fields (`use_responses_endpoint`, `system_prompt`, `bash_classifier_url`, `toast.enabled`) — never provider/model — and always to the **global** config only (`mergeAndWriteGlobal`; settings are user-level preferences, not project-specific configuration). This prevents project-level provider/model overrides from leaking into global config. The General tab holds the `use_responses_endpoint` and `toast.enabled` toggles; reasoning is not a settings-panel concern — it is controlled per-model via the model picker and persisted session-scoped (see **Reasoning effort lifecycle pattern**). Write-time validation mirrors the parser: `validateSystemPrompt` counts UTF-8 code points against the shared `config.max_system_prompt_chars` (a byte-length check would falsely reject a CJK prompt three bytes per char), and an invalid value is refused at BOTH commit (Enter — a transcript notice now explains why nothing was committed) and save (Ctrl+S). `mergeAndWriteGlobal`/`mergeAndWriteProject` refuse with `error.ConfigRoundTripLoss` when the on-disk re-read produces diagnostics (invalid JSON, over-limit `systemPrompt`/plugin `settings`): the re-read already dropped those values, so an unchecked rewrite would erase them from disk with no signal — the file is left untouched and the caller surfaces the failure. A cleared field is encoded as an empty pending string (`null` means untouched): `applyTextOverlay` maps an empty update to field removal and `serialize` never writes `""`, so Delete-key clears actually reach disk. Tests: `"mergeAndWriteGlobal refuses to rewrite a config that would lose fields"`, `"validateSystemPrompt counts UTF-8 code points like the parser"`, `"clearCurrentField marks a set field cleared and dirty"`.

### Bounded classifier fetch pattern (`src/tools/bash_safety.zig`)

The remote safety-classifier call (`classifyOverSocket`) is a hand-rolled, deadline-bounded HTTP/1.1 exchange over a raw socket — NOT `std.http.Client`. It polls the socket with the remaining budget (`receiveResponseBounded`) into a fixed 16 KiB buffer, frames the response by EOF (`Connection: close`, which the uvicorn sidecar honours), and fails open to the local matcher on timeout/oversize/malformed responses — the same fail-open contract as every other classifier failure. The AI wire clients remain on `std.http.Client`; their shared transport wraps the `Io.Threaded` read callback on POSIX so the `EAGAIN` from `SO_RCVTIMEO` becomes `error.Timeout` instead of Zig 0.16.0's `errnoBug` panic in Debug / `error.Unexpected` in ReleaseFast. That timeout applies to the response body after its head; connect and response-head reads remain on the standard client's unbounded path. Windows and `https://` classifier URLs keep the plain `fetch` exchange without a deadline (documented in `docs/wiki/SAFETY_CLASSIFIER.md`). The classifier deadline is receive-only — send (blocking stream write) and connect (kernel-default; `Io.Threaded.netConnectIpPosix` panics on `ConnectOptions.timeout`, a std TODO) remain unbounded, matching the pre-deadline behavior.

### Mention and image ingestion

- **Mention/image ingestion caps.** `at_mention.zig` caps a single file mention at 64KB (`per_file_mention_max_bytes`), an aggregate of 256KB per turn (`turn_mention_aggregate_max_bytes`), and 4 images per message (`max_images_per_message`). Oversized files are read as a head+tail sandwich (first half + last half of the budget, joined by `common.elideMiddle`) so a plan's load-bearing conclusion at the tail survives, with a `[file truncated: {n} bytes — re-read via shell if you need the rest]` notice; over-cap images are skipped, not truncated. The elision format is the shared `common.elideMiddle` SSOT (also used by `pruneToolText` for tool-result truncation).

### View cache across run-loop iterations (TD-13, shipped)

`Agent.run` calls `context_assembly.pruneHistoricalToolResultsViewsCached(gpa, &self.tool_view_cache, …)` in the run loop (`src/agent.zig` — grep the call site; line numbers drift), up to `context.toolCallLimitPerTurn` iterations/turn (default 100, accepted 1–1000). The **naive** cache (reuse views when `messages.len` is unchanged) is **unsafe**: `MessageView.borrowed` points into the ContextManager's ArrayList backing, which `appendPersisted` may reallocate — dangling every borrow even when the length later matches. Per-index pruned copies ARE stable (pruning of message *i* depends only on `messages[i]` and the cap), so `PrunedToolCache` (`src/context/assembly.zig`) caches only the **owned** pruned copies keyed by index; borrows are re-resolved against the live items slice every iteration, which is what makes the borrow safe. Invalidation: `Agent.tool_view_cache.clear()` on history swap/reload (`src/agent.zig`), and `deinit` frees it. Do not bypass the cache with the uncached `pruneHistoricalToolResultsViews` in the run loop. Regression test: `"PrunedToolCache caches owned messages across iterations with pointer stability"`.

### Type System Discipline pattern

Use `union(enum)` instead of flat structs with optional fields whenever a value can be in one of several mutually-exclusive states. This makes illegal combinations unrepresentable at compile time. Current types following this pattern:

- `ai.ChatMessage` — `union(enum) { system, user, assistant, tool }`. The `tool` variant carries non-optional `call_id`; other variants cannot. `role()` and `text()` are cross-variant accessors.
- `transcript.Message` — `union(enum)` with 10 variants (`user`/`agent`/`skill`/`logo`/`thinking`/`status`/`notice`/`success`/`info`/`tool`). `Basic` and `ToolView` payload structs group fields by category. `kind()` bridges the loose `MessageKind` enum; `mirror()` is test-only flat view.
- `tools.Output.display` — `Display` union with `none`/`text`/`diff` variants, replacing the old `?[]u8 + DisplayKind` pair that allowed `null` with `.diff`.
- `config.McpServerConfig.transport` — `union(enum) { stdio, sse }`. A server is either stdio (command+args) or sse (url), never both or neither.
- `mcp.McpClient` — `transport: union(enum) { stdio, sse }` (static config) + `lifecycle: union(enum) { disabled, stdio, sse, failed }` (runtime state). `status()` maps lifecycle to the legacy `ServerStatus` enum.
- `config.Config.model_selection: ?ModelSelection` — typed view replacing 9 loose optional fields. `ModelSelection` is `union(enum) { builtin, custom }`: builtin carries `provider: Provider` + `provider_name`; custom carries `provider_name`, `base_url`, `api_key`. Optional settings (`use_responses_endpoint`, `system_prompt`, `bash_classifier_url`) live on both variants. Callers use accessors (`provider()`, `providerName()`, `model()`, `baseUrl()`, `apiKey()`, `useResponsesEndpoint()`, `systemPrompt()`, `bashClassifierUrl()`) so builtin/custom differences are hidden. The old `enableThinking`/`enable_thinking` config key is accepted-but-discarded at parse (reasoning is per-model via `providers.<name>.models.<id>.reasoningEffort`); it is not a field on `Config` or the selections anymore. `applyConfigOverlay` treats `model_selection` as canonical and propagates `provider_name` to the target's legacy field; `syncModelSelectionFromLegacy` mirrors legacy changes back into it. `parseObject` only populates `model_selection` when all required fields are present — since `api_key` is never serialized (lives in `auth.json`), disk-loaded configs **never** have `model_selection`. Callers that need `model_selection` after a fresh load must fall back to legacy fields (`config.provider`, `config.model`, `config.base_url`, `config.provider_name`), which ARE populated from `defaultModel` and `hydrateActiveModel`. **Zig footgun (crashed resume, fixed in 58a0537):** `Config.activeModelSelection()` and the owned `ModelSelection` accessors (`model()`, `providerName()`, `baseUrl()`, …) MUST take pointer captures (`|*ms|`, `|*b|`/`|*c|`) / a `*const ModelSelection` receiver. A *value* capture hands back `&b.model` / `b.provider_name` pointing into the method's popped stack frame — the caller's later reads (e.g. `reasoning.resolve()` after an intervening client-attach call) then hit "switch on corrupt value" on garbage. Method-call syntax auto-references values, so pointer receivers need no call-site changes; the returned pointers resolve into the caller's own storage.
- `tui.AtSearchState` — `union(enum) { closed, indexing, open }` with `IndexingPayload` and `OpenPayload` structs. `kind()`/`results()`/`close()` helpers bridge callers.
- `tui.NavState.quit` — `QuitState = union(enum) { none, pending, confirmed }` replacing `?Timestamp + bool`.
- `tui.NavState.session_action` — `SessionAction = union(enum) { browsing, renaming, deleting, blocked }`. Sub-states for the resume picker: `browsing` is normal navigation; `renaming` shows a text prompt; `deleting` shows Y/N confirmation; `blocked` shows a popup (e.g. "Cannot Delete Active Session"). Any key dismisses `blocked`; `renaming`/`deleting` submit on Enter and cancel on Esc.
- `tui.NavState.resume_group_by` — `ResumeGroupBy = enum { flat, project, date }` replacing `resume_global: bool`. Cycles via `Ctrl+A`: flat (current project only) → project (all projects, grouped by project) → date (all projects, grouped by date bucket: Today/Yesterday/This Week/This Month/This Year/Older). Tab only folds/unfolds in `.project` mode.
- `tui.ModelCatalogue.load` — `LoadState = union(enum) { idle, loading, failed }`.
- `search.Backend.state` — `State = union(enum) { idle, loading, ready, failed }`. The `.ready` arm owns a slab of null-terminated filepaths plus a count; matching is performed by the vendored `fzy` C library (`vendor/fzy/src/match.c`).
- `tui.MetricsState.diff` — `DiffState = union(enum) { idle, loading, ready, refreshing }`. The `refreshing` arm keeps the old cache while a new fetch is in flight. Backward-compat accessors (`diff_refresh_future`, `diff_refresh_done`, `diff_loading`, `diff_refresh_again`, `diff_cache`) preserve existing call sites after the flat-to-union migration.
- `config.ProviderModel = Model` — type alias removing duplicate struct drift.
- `config.BaseUrl` — `union(enum) { default, custom: []u8 }`. In overlay merges, `.default` means "don't override"; at final resolution it falls through to `Provider.defaultBaseUrl()`.
- `config.ReasoningSetting` — `union(enum) { unset, effort: ai.ReasoningEffort }`. Follows `BaseUrl`'s overlay-merge pattern: `.unset` means "not specified in this layer, don't override"; `.effort` carries an explicit level (including `.default` which omits the `reasoning_effort` request parameter). `resolve()` falls back to `.medium` for `.unset`.
- `session.SessionSummary.leaf_entry_id: ?EntryId` — branded `EntryId` (fixed-size `[entry_id_len]u8`) instead of loose `[]u8`.
- `model_loader.ModelSource` — `union(enum) { openai_codex, openai_compatible: Compatible }`. The `.openai_compatible` arm is a `Compatible` struct `{ provider, base_url, auth_key_id }` (all gpa-owned; `source.deinit(gpa)` frees the strings) rather than a bare `Provider` enum. A bare enum collapsed every dynamic/config provider (StepFun, Kimi, …) to `.openai_compatible`, so a multi-provider catalogue couldn't tell them apart and `applySelectedModel` connected to whichever URL was stashed in `cached_config`. Carrying the full connection per row makes the mismatch unrepresentable: `applySelectedModel` reads the selected entry's `conn` directly and never consults `cached_config.base_url`. The disk cache (`model_cache.Record`) serializes `authKeyId` (cache version 2; v1 is read back compatibly, resolving `auth_key_id` from the configured provider label).
- `tools.Schema.Property` — `nullable: bool` flag supporting OpenAI strict-mode union types (`["string","null"]`); `enum_values: ?[]const u8` for OpenAI enum schemas; `default_value: ?[]const u8` for JSON fragment defaults. The schema writer emits nullable union arrays only when `nullable` is set, while keeping nested object `additionalProperties: true` for free-form fields like `env`. Strict-mode emission (`"strict":true`, `additionalProperties:false`, and `required:[all properties]`) is gated by the `strict: bool` parameter (see the Tool schema strict-mode pattern below); when strict is off, `required` lists only genuinely-required properties and the `"strict"` key is omitted. `deinit(gpa)` frees owned `enum_values` and `default_value` slices.

### Models.dev provider filtering pattern

`parseModelsDevJson` in `src/models/registry.zig` includes any provider with a non-empty `api` field, a string `name` field, and ≥1 model — npm package identity is irrelevant. The `api` field is the ground-truth signal for Zay's `openai_compatible` adapter. `@ai-sdk/anthropic` providers with custom `api` endpoints (kimi-for-coding, minimax, etc.) are included; `@ai-sdk/openai` providers without `api` (openai, perplexity-agent) are excluded because `Provider.base_url` is non-optional. Providers without an `api` field (`@ai-sdk/google`, `@ai-sdk/azure`, etc.) are correctly excluded.

### Models.dev network-first loading pattern

`loadOrFetchRegistry` tries sources in order: (1) network fetch from `https://models.dev/api.json` with User-Agent `zay/1.0`, (2) fresh cache (within 24h TTL), (3) stale cache (ignoring TTL), (4) vendored snapshot at `<exe_dir>/../share/zay/api.json` (installed by `zig build install`), (5) builtins-only fallback. The vendored snapshot seeds the cache directory (`~/.config/zay/cache/models.dev/api.json`) so subsequent starts skip the file read, ensuring 145+ dynamic providers are always available offline. The TUI loads the registry through `ensureModelsDevRegistry` (`src/tui/provider_model.zig`): it fetches/parses only when `provider_state.modelsdev_registry` is still null and relies on a background refresh job afterwards — the picker intentionally uses the disk-cached registry and never does network I/O on open. Diagnostic logging at each stage (`modelsdev.fetch.ok`, `modelsdev.fetch.failed`, `modelsdev.cache.fresh`, `modelsdev.cache.stale`, `modelsdev.vendored`, `modelsdev.registry.fallback`) helps diagnose empty provider lists.

- **Models.dev Registry Allocations:** `modelsdev.Registry` string storage uses an `ArrayList(u8)`. To prevent dangling slice pointers when building or merging providers, accumulate string offsets via `StringRef` (`start`, `len`) and resolve slice pointers only after all string appends complete. In `buildRegistry`, resolve `providers`/`models` slices only AFTER the model-id appends too — resolving `providers` before the model loop leaves its `id`/`name`/`base_url` slices dangling when `strings` reallocs to fit the model ids (api.json carries hundreds of models, so a realloc is guaranteed → SIGABRT in the picker). Regression test: `"buildRegistry provider slices survive model-string realloc"`.

- **Models.dev payload size cap is ONE constant (2026-09-14).** `registry_payload_max_bytes` (`src/models/registry.zig`, 16 MiB) bounds all THREE api.json readers — the network fetch, the disk-cache read, and the vendored `<prefix>/share/zay/api.json` read. It exists because api.json crossed the previously per-site 4 MiB literals in the wild (4.66 MB as of 2026-09-14), which failed all three readers at once (`fetch.failed err=ResponseTooLarge`, `vendored.failed err=StreamTooLong`) and silently left `/connect` on builtins-only. Never re-introduce per-site literals; the cap covers DECOMPRESSED bytes. Regression test: `"registry payload over the old 4 MiB cap parses"`.

### HTTP fetch decompression pattern

`fetchApiJson` in `src/models/registry.zig` must honor `response.head.content_encoding`: gzip/deflate/zstd responses from Cloudflare-backed hosts (models.dev) are decompressed via `response.readerDecompressing` before caching; identity responses pass through unchanged. Using a plain `response.reader` stores compressed bytes in the cache, which `parseModelsDevJson` rejects, silently falling back to builtins-only (18 providers). `listModels` in `src/ai/openai_compatible_models.zig` already follows this pattern; `fetchApiJson` must match it.

### Dynamic provider connection pattern

When a models.dev dynamic provider is selected, `submitDynamicProviderSetup` stashes the provider's `base_url` and the user's API key into `cached_config` before entering the model picker, and stores two identity fields: `dynamic_provider_name` (human-readable, e.g. "StepFun AI", used by the status bar) and `dynamic_provider_id` (the auth.json key, e.g. "stepfun-ai"). Both are **runtime-only** — never serialized to config.json

**Selection-time resolution no longer reads `cached_config`:** `applySelectedModel` resolves the connection URL and key **directly from the selected entry's own `ModelSource`** — `ModelSource.openai_compatible` is a `Compatible` struct (`{ provider, base_url, auth_key_id }`), so each catalogue row carries its own full connection. `applySelectedModel` calls `compatibleApiKeyForConn(conn)` (auth.json lookup by `conn.auth_key_id`, fallback to anonymous/local) and `attachOpenAiCompatibleClient(conn.base_url, ...)`. The `cached_config.base_url`/`dynamic_provider_id` stash is now only for **session resume** (`tryAttachOpenAiCompatibleFromConfig`) and `hasOpenAICompatibleCredentials`; `updateCachedModelSelection` mirrors the entry's `conn` into the stash so resume stays consistent. This closed a class of multi-provider bugs where `cached_config.base_url` held a single global value and selecting a model from a different provider (in a `connected_provider` sweep) connected to the wrong endpoint or returned `NotConnected`. `compatibleBaseUrl`/`compatibleApiKey` (the provider-enum variants) are now test-only; do not reintroduce them on the selection path — use `compatibleApiKeyForConn` and the entry's `conn.base_url` instead.

### Dynamic provider persistence pattern

`serialize` writes `defaultModel: "provider_name/model_id"` as the single source of truth for provider identity — there is no separate `"provider"` field. `parseModelSelection` splits on the first `/` to recover `provider_name` and `model_id`. After restart, `model_selection` is usually null (because `api_key` is never serialized), so all rehydration paths fall back to legacy fields: `tryAttachOpenAiCompatibleFromConfig` resolves `base_url` from `config.base_url` (hydrated from the `providers[]` map by `hydrateActiveModel`), `model_id` from `config.model`, and the API key from `auth.json` via `config.provider_name`. `hydrateActiveModel` includes a recovery fallback: when `provider_name` is the generic enum label (`"openai_compatible"`) — e.g. from configs written before the `provider_name` serialization fix — it matches `.openai_compatible` entries in the `providers[]` map by enum and repairs `provider_name` to the actual id. `providerDisplayName` and `providerLabel` in `status.zig` fall back to `config.provider_name` / `config.provider` when `model_selection` is null. `buildMergedProviderList` Layer 3 skips config entries covered by the models.dev registry (`reg.lookup(cp.name)`) to prevent the persisted `ProviderConfig` from shadowing the `.dynamic` handle. `collectConfiguredProviders` block 3 uses a `covered_by_registry` guard (with `ms.provider_name` fallback for resume) and resolves the API key from `provider_state.api_keys` instead of the always-empty `ms.api_key`

**Disk cache (`collectModelCacheConfigured`) must mirror the online collector's two dynamic/config rules:** (a) every `.openai_compatible` entry in `cached_config.providers[]` with a custom `base_url` and a key in `auth.json` (config map key == `auth_key_id`), and (b) every models.dev dynamic provider present in `provider_state.api_keys` (key == registry id). The earlier code wrote only the single `model_selection` provider, so other connected dynamic providers vanished on restart. **Conn-keyed drops, never enum-keyed:** `dropConn` (catalogue) / `dropModelsForConn` (job) / `installModelLoadResult`'s merge `StringHashMap` are always keyed by `conn.auth_key_id` (or the full `(provider, base_url, auth_key_id)` triple), never by `conn.provider`. Enum-based `dropProvider` is correct **only for builtin catalogue providers** (each is its own enum value); on multi-`.openai_compatible` provider lists it collapses siblings and deletes unrelated providers in a single refresh. `openModelPicker` calls `ensureModelsDevRegistry` before `restoreModelCache` so the cache collector can see dynamic providers (the registry is otherwise loaded only by `openProviderPicker`). `startOpenAiCompatibleModelLoad` uses `.merge = true` (consistent with `startProviderModelLoad`) so adding dynamic/config providers preserves the existing catalogue and appends to it instead of wiping it via `codexModelsClear`.

### Mid-session model persistence pattern

The picker must mirror a model switch into the session DB, not only `config.json`. `applySelectedModel` resolves a `provider_name` (`Provider.openai.label()` for codex, `conn.auth_key_id` for compatible) and, after a successful client attach, calls `session_writer.updateModel(provider_name, model_id)` — the same call `runtime.applyFromConfig` makes. Without it the picker bypassed the session write, so `initResume` restored the stale creation-time model on restart. The write is **best-effort** (logged on error, never rolls back the applied client switch) and gated by `AgentRuntime.session_writer_started` (default `false`, set `true` in `initSession` after the writer thread is up). The gate exists because TUI test harnesses construct a partial runtime with `session_writer = undefined`; the flag lets them exercise the picker without touching sqlite. `hasOpenAICompatibleCredentials` was relaxed to match: since `api_key` never serializes, gating purely on the runtime stash made the disk-cache restore (`/models`) skip the dynamic provider on restart. The typed `model_selection` with a non-empty `baseUrl()` is now the durable signal (real key resolved from `auth.json` at fetch time); `shouldLoadConfiguredCompatibleCatalog` resolves `base_url` from `model_selection.baseUrl()` when the legacy stash is null. `model.id.len == 0` is guarded by `return error.EmptyModelId` before constructing the non-optional `ModelSelection.custom.model.id` — use a real early return, never `std.debug.assert`, because `unreachable` is UB in ReleaseFast (the install target) and would not protect that build.

### Typed callback pattern

`agent.Listener(Ctx)` and `executor.ToolCallObserver(Ctx)` are generic over the consumer's context type. The `*anyopaque` + `@ptrCast` vtable is replaced by `*Ctx` + typed callback functions. `StreamContext(L)` and `ExecutorBridge(L)` are generic over the listener type. The only remaining `@ptrCast` **on the listener/observer seam** is `BashApproval` (1 site, deferred because making it generic would require `Agent` itself to be generic); the compaction `Env` still uses a separate `*anyopaque` callback table (`agent.zig`).

### Manual compaction trigger pattern

`Agent.forceCompact()` is a synchronous public method that runs the full compaction cycle (snapshot → summarize → swap) and returns `!Event.HistoryCompacted` with token counts before/after. Unlike the automatic path (which runs between turns inside `agent.run()`), this is callable from the TUI command handler. The caller is responsible for turn-safety: check `app.thread.turn.isActive()` before calling. Errors are surfaced to the user via transcript notices rather than swallowed in logs.

### Config layering pattern

Zay merges global (`~/.config/zay/config.json`), project (`.zay/config.json`), and env-var overlays into `cached_config`.

**Schema v2:** JSON keys are camelCase (`defaultModel`, `baseURL`, `mcpServers`, `useResponsesEndpoint`, `strictOutputs`, `systemPrompt`, `bashClassifierUrl`); legacy snake_case keys are parsed for backward compatibility but are **not schema-valid** — `schema/config.schema.json` uses `additionalProperties: false`, so a strict validator rejects them even though Zay's parser accepts them and rewrites them as camelCase on the next save. The legacy `enableThinking`/`enable_thinking` key is accepted-but-discarded (reasoning is per-model via `providers.<name>.models.<id>.reasoningEffort` — see **Reasoning effort lifecycle pattern**). `defaultModel`'s schema pattern `^[^/]+/.+$` requires both halves non-empty (the parser splits on the first `/` and imposes no charset restriction — model ids like `gemma4:31b` parse fine). `version` is a semver-style digits-and-dots string (`"2.0.0"`; a bare major is accepted, a major above 2 raises an `unsupported schema version` diagnostic); legacy integer `1` normalizes to `"1.0.0"`. `applyConfigOverlay` uses an if/else structure: `model_selection` is canonical; legacy fields are fallback. `syncModelSelectionFromLegacy` mirrors legacy changes back into `target.model_selection` via `|*ms|` pointer capture. `serialize` skips `api_key` (lives in `auth.json`) and writes camelCase keys. `saveSettings` writes only settings-managed fields — never provider/model. At connection time, `tryAttachOpenAiCompatibleFromConfig` and `tryAttachOpenAiResponsesFromConfig` resolve an empty `ms.base_url` through `provider.defaultBaseUrl()` so client `init` never sees an empty URL.

- **Session config copy semantics.** `session_config` is a value-copy of `config`; union fields are shallow-copied, so mutating a union field on the copy doesn't affect the original.

### Reasoning effort lifecycle pattern

Reasoning is controlled per-model and flows through a single chain: model picker (`Model.reasoning_options` from config `reasoningOptions`, cached in `app.provider_state.reasoning_opts_cache`; empty = global hardcoded list) → `selectedReasoningEffort()` → `attachOpenAiCompatibleClient(effort)` / `persistModelSelection` → wire. The wire field is dialect-gated (`ai.WireDialect`, Phase 1): DashScope uses top-level `enable_thinking`, OpenRouter uses a `reasoning` object (`{"effort":"...","summary":"..."}`), every other provider gets flat `reasoning_effort` (`.none` → `"none"` or `enable_thinking:false`). Effort levels: `default/minimal/low/none/medium/high/xhigh/max` (`max` is OpenRouter-specific, highest above xhigh). The session DB stores the active effort label in `sessions.reasoning_effort` (schema v5, nullable; NULL = "use config/default"). `Session.updateModel(provider, model_id, effort_label)` writes it from `applyFromConfig` (resolves `model().reasoning.resolve().label()`) and `applySelectedModel`; `initResume` restores it via `ai.ReasoningEffort.fromString` (invalid DB labels degrade to "no override", never fatal). The status bar shows the live effort (`src/tui/status.zig`, `ModelStatus.reasoning`, source priority: live client config → model selection → "medium") as `provider · model [effort]`. The model picker no longer has a SCOPE column — the save scope (global/project/session) is cycled with **Ctrl+S** inside the picker and displayed in the footer status line next to a wire-parameter preview (`→ reasoning_effort:"high" (Ollama)`, `enable_thinking` for DashScope).

**Ollama Cloud / local Ollama `reasoning_effort` clipping (added 2026-08-09).** Both Ollama Cloud (`https://ollama.com/v1`) and local Ollama (`http://localhost:11434/v1`) use the **OpenAI-compatible `/v1/chat/completions`** endpoint — NOT the native `/api/chat` format. The native `/api/chat` fields (`think`, `format`, `options`, `keep_alive`) are absent on `/v1`. Ollama's `openai.go` validates `reasoning_effort` **strictly**: only `high`/`medium`/`low`/`max`/`none` are accepted — sending `xhigh` or `minimal` returns HTTP 400 (`"invalid reasoning value: '...' (must be \"high\", \"medium\", \"low\", \"max\", or \"none\")"`). Both invalid values are reachable on Ollama Cloud because the builtin registry entry declares no per-model `reasoning_options`, so the global hardcoded list (which includes `xhigh` and `minimal`) is offered. `wireEffortLabel` (`ai/model_compat.zig`, re-exported by `openai_compatible.zig`) clips them for the `.minimal` dialect only — `xhigh → "max"`, `minimal → "low"` — while the `.openai` dialect keeps the raw label (gpt-5 honours both). The stream parser recognises `delta.reasoning` as the reasoning field (Ollama's `/v1` response; DeepSeek/others use `reasoning_content`, and `thinking` is recognised as a fallback for OpenAI-compatible proxies that forward Ollama's native field name). Tool calls come back in the standard OpenAI shape (`message.tool_calls[].id/function.name/function.arguments`); `tool_choice:"auto"` is silently dropped by Ollama (unsupported) but harmless to send.

**Two-layer clipping composition — ONE named home (2026-09-14).** `wireEffortLabel(dialect, effort)` is the **dialect layer only**; `clipEffortForModel(model, label)` is the **model layer only**: Qwen / DashScope rejects `high`/`max`/`minimal` (valid set `low`/`medium`/`none`/`xhigh`), so it maps them to `medium`/`low`; every other model passes through. The composition has ONE named home — `model_compat.resolveEffortLabel(model, dialect, effort)` — which BOTH wire serializers call; no call site composes the pair by hand. Never fold one concern into the other — the split is what makes Ollama+Qwen work (dialect passes `high` through, model layer clips it). The Qwen gate `isQwenModel` is **case-insensitive prefix matching** (`qwen*`/`qwq*`) because HuggingFace/vLLM ids are capitalized (`Qwen/Qwen3-32B` — vllm-project/vllm#41114); a byte-level `startsWith` misses exactly the vLLM-hosted Qwens. The Responses API path (`useResponsesEndpoint: true`, opt-in) was initially a bypass — Ollama's `/v1/responses` silently ignores unknown reasoning fields (Go's default JSON decoder drops them, and the endpoint defines no reasoning struct), so it wasn't crash-causing, but clipping keeps the two clients consistent and is forward-safe. The `include:["reasoning.encrypted_content"]` emitted unconditionally by `responses_request` when reasoning is set is also silently ignored by Ollama's `/v1/responses` — left as-is because it's harmless noise and suppressing it for `.minimal` would require broader dialect-gating of the Responses API client.

### Qwen message normalization

- **Qwen single-leading-system normalization.** Qwen3.x ship a strict Jinja chat template that raises `System message must be at the beginning` on more than one `system` message or a non-leading one. `normalizeMessagesForQwen` (`ai/model_compat.zig`) merges all `system` messages into one (text blocks joined by `\n`) and hoists it to index 0; the gate is computed at the call site (`dialect == .dashscope or isQwenModel(model)`) so non-Qwen history is never rewritten. Ownership: the result carries a `rebuilt` flag — passthrough shares the caller's storage, rebuild owns exactly one merged system block; free ONLY via `deinitNormalizedMessages(gpa, list, rebuilt)`, which frees the owned block on rebuild and just the list storage otherwise.

### Context & compaction config pattern

Context usage before a provider measurement includes the pruned message estimate
and the current client's serialized tool catalog (`LanguageModel.estimateToolTokens`,
bytes/4). The real input/output usage anchor already includes tools; only catalog
changes since that anchor adjust it. Tool definitions remain runtime state, not
session messages. `request_usage` entries preserve provider token measurements
as metadata; branch projection and compaction never emit them into the model's
history.

`Config.context: ContextSettings` carries `overrideContextWindow`, `maxOutputTokens`, `disablePromptCache`, and `compaction: CompactionSettings` (auto, threshold, keepRecentTokens — the old `bufferTokens` was removed, it never did anything). The runtime stores `context_settings` and passes `override_context_window` to `compaction.contextWindowTokens()` at client attach time. The agent stores `compaction_settings` and passes `threshold` to `shouldStartSummary`/`shouldSwap` and `keep_recent_tokens` to `keepRecentTokens`. When `auto` is false, `maybeCompact` returns immediately. The swap watermark is `threshold + 0.20` (capped at 0.95); `threshold` is accepted in [0.1, 1.0] and clamped down to the 0.90 ceiling at parse time (values outside the band are dropped and the 0.75 default is used) so the swap watermark can never fall below the start watermark. `startCompaction` calibrates the keep-recent budget by the ratio of the provider's real token count to the chars/4 estimate (`calibrateKeepBudget`) so CJK text keeps fewer messages and still compacts below swap. Background-summarizer clients (codex / responses_core) receive the minimal `compaction.summarizer_system_prompt` — never the full agent system prompt — so the summary request itself fits a small window. The automatic path carries a circuit breaker: after 3 consecutive failures it backs off (one transcript notice, `compaction_notice` event) and only `/compact` remains. `forceCompact` drains any in-flight background summary before starting (TD-1), as does `navigateToEntry` before a branch switch (TD-2). JSON Schema for editor autocompletion lives at `schema/config.schema.json`.

**Codex Responses encrypted-reasoning replay:** `ResponsesConfig.include_encrypted_reasoning` and `scrub_encrypted_reasoning` are internal transport settings, not user configuration fields; do not add them to `schema/config.schema.json` or `docs/CONFIG.md`. The standard Responses client keeps encrypted reasoning enabled and preserves persisted `responses_item_json`. The ChatGPT Codex transport disables the server include and enables replay scrubbing because the Codex backend rejects persisted `encrypted_content` with a misleading 400. The scrubber removes only the top-level `encrypted_content` field, skips malformed/non-object JSON without failing the request, and is covered by tests for both Codex cleanup and standard Responses preservation. Keep these controls separate: requesting encrypted reasoning and sanitizing replayed history are different concerns.

**`disablePromptCache` (C1, added 2026-08-06):** a user-facing escape hatch for OpenRouter `:free` / gateway-fronted models (kimi, inclusionai/ling) that reject `cache_control` and/or `session_id`/`prompt_cache_key` with HTTP 400. When true, the flag suppresses ALL cache fields in BOTH wire clients — OpenRouter top-level `cache_control` + native `session_id`, OpenAI `prompt_cache_key` (chat-completions AND Responses-API `responses_request.writeRequestPayload`, the latter being ungated by dialect today) — regardless of the resolved `WireDialect`. It flows `context.disablePromptCache` → `AgentRuntime.disable_prompt_cache` (set at the dialect-resolution site in `tryAttachOpenAiCompatibleFromConfig`, read from `context_settings` for ALL client kinds) → `ai.Config.disable_prompt_cache` on every attached client (main/compaction/naming for all three client kinds). It is also the durable complement to the automatic C2 downgrade retry (`errorDetailMentionsCache`) — set it once for a known-bad model and never see the 400.

**`toolCallLimitPerTurn` / `softStopOnToolCallLimit` (added 2026-08-22):** the per-turn limit bounds both individual tool calls and `Agent.run`'s model-response iterations. Every call in a parallel assistant batch consumes one call from the same limit; if the batch exceeds the remaining budget, only its allowed prefix is dispatched and failed results are recorded for the skipped calls. Both keys live under `context.*` and parse in both camelCase and snake_case (`u32fieldCompat`/`boolFieldCompat`, camelCase wins; 1–1000, out-of-range dropped). They resolve onto plain `Agent` fields in `initSession` right after the `compaction_settings` copy — following that pattern, NOT the client-attach resolution — so test-built agents keep working off field defaults and every runtime flavor (primary, `/new`, `/resume`, lane workers) inherits them. On exhaustion with soft-stop enabled, `softStopOnBudget` drains the whole queued-message backlog into history (`drainAllQueuedToHistory` + `queued_messages_flushed`), appends a static `[zay]` continuation hint, and emits the allocation-free `tool_budget_exhausted: u32` event before returning normally — the run always terminates, continuation is the user's next submit (TD-6: no auto-resume). The hint is a `.user` machine message, deliberately NOT `.system`: `SessionWriter.append` skips `.system` (writer.zig), so only `.user` survives `/resume`, branch switches, and compaction reprojection — and Qwen's single-leading-system normalization never touches it. With `softStopOnToolCallLimit: false` the loop keeps the historical `error.ToolCallLimit` contract byte-for-byte.

**`autoContinueOnLengthCut` + finish_reason visibility (added 2026-09-09):** one-shot auto-continue for responses severed at the provider's output token cap. `stream_parser.parseChoiceObject` now parses `finish_reason` (previously `skipValue`d — a `length` cut was indistinguishable from a clean stop) into `ChunkChange.finish_reason` (excluded from `empty()`, mirroring `usage`); `readStream` accumulates it last-wins into `Turn.finish_reason` (`ai.FinishReason`). The Responses API has parity: `response.incomplete` was previously an unknown event (warn + dropped → `error.ResponseIncomplete` failed the whole turn, losing the streamed prose); `responses_events` now treats it as a deliberate terminal — a separate `Terminal.incomplete` flag (never overload `completed`: a stream ending with NEITHER is still truncated) — and maps `incomplete_details.reason` (`max_output_tokens` → `.length`, `content_filter` → `.content_filter`, else `.other`), reusing `parseResponseUsage` so the truncated turn's real token counts reach the compaction budget. Codex's websocket loop breaks on either terminal (`state.terminal.completed or .incomplete`) — an incomplete frame that kept looping would stall until the idle watchdog fired. In `Agent.run`'s zero-tool-call branch, `handleLengthCut` (the testable twin of `softStopOnBudget`; queued user messages take precedence over it) emits the allocation-free `length_cut` event: `.auto_continued` appends the `[zay]` `length_cut_continuation_hint` `.user` message and re-requests ONCE per run (the `length_continued` flag lives in `run`, so a run-level cut can never loop extra billed requests), `.stopped` ends the turn; `turn_view` renders both as amber "output" notice rows. Two `log.warn` guards close the related silent-truncation blind spots: a tool_call builder that streamed id/arguments but no name (`readStream.nameless_tool_call_dropped`), and `finish_reason=tool_calls` with zero parsed/recovered calls. Origin: model.inferx.net `deepseek-v4-flash` ended turns as "…ekliyorum:" prose with no tool call (~15 of 40 text-only ends in one session); the user re-prompted "devam et" 14 times in 21 minutes.

**AutoCompactor ownership:** `context/auto_compactor.zig` owns the watermark, breaker, manual-compact two-phase flags, and cancellable summarizer-task lifecycle. The summary runs in a `std.Io.Future`: normal application awaits it, while exit, client replacement, and session navigation cancel and await it before freeing its client or allocations. Drain discards even a concurrently completed summary and resets manual-submit flags; Canceled, rejected, empty/whitespace-only, or provider-truncated/filtered summaries never persist a compaction boundary or replace context. The POSIX HTTP reader preserves socket deadlines using nonblocking reads and cancellable waits, and transport cancellation bypasses retries. Limiter release is uncancelable so teardown cannot leak a provider permit. Context reprojection reserves capacity before discarding old messages, leaving the live cache intact on allocation failure. Its per-call `Env` carries client, limiter, session writer, window, settings, tool cost and `historyCount`/`estimateTrailing`/`estimateAll`/`swap` callbacks. Agent sequences `maybeCompact` once per turn iteration and `recordUsage` after each reply. The `swap` callback persists `appendCompaction` before `reloadFromSession`; `Event.CompactionNotice` and `HistoryCompacted` are defined in the compactor and re-exported by `Agent.Event`.

### External Database Service & Roaming Session Backend (2026-09-28)

Zay unifies local embedded SQLite and external database backends through `SessionBackend` (`src/session/backend.zig`). The active remote backends are the REST companion service (`zay_service`, implemented by `db.Service`), direct Turso/LibSQL HTTP, and direct Cloudflare D1 HTTP. When configured via the `database` block or the legacy `databaseServerUrl` / `ZAY_DATABASE_SERVER_URL` settings, Zay delegates session history, timeline branches, and resume points to the selected backend. The companion service can use SQLite or PostgreSQL; `postgres_native` is accepted by the parser but remains unimplemented.

**Key Invariants & Mechanics:**

The common `SessionWriter` admits entries to a bounded queue before updating the
message cache; admission is not a durable commit. On a write failure it retains
the failed entry, warns, stops later writes, and propagates the error through
enqueue and all quiescing read/navigation operations. This prevents incomplete
DB history from replacing live history. The same policy covers SQLite, REST,
Turso, and D1. HTTP commit outcomes can be uncertain, so the writer does not
blindly retry or switch stores mid-session. Uncommitted entries remain in memory
until teardown, where a warning reports the failure; this is not an offline
durability guarantee.

1. **Atomic Batch Invariant (`INV-DB-BATCH`):**
   Stateless HTTP REST database services (like `tools/db_server/`) use connection pools. They cannot safely maintain an interactive SQL transaction across separate HTTP requests (`BEGIN` -> `INSERT` -> `COMMIT`) because distinct requests may checkout different pool connections. All multi-statement remote mutations MUST be executed via the atomic batch endpoint (`POST /v1/batch` -> `SessionBackend.execBatch` / `Session.appendQueuedPayload`). Calling `beginTransaction`, `commitTransaction`, or `rollbackTransaction` on a `.remote_service` backend explicitly raises `error.UnsupportedTransaction`.
2. **Roaming & Machine Identification (`host_id`):**
   Schema migration 8 adds a nullable `host_id TEXT` column to both `sessions` and `lanes`. At session creation, Zay resolves the host identifier once in this order — `ZAY_HOST_ID`, `COMPUTERNAME`, `HOSTNAME`, then `"default-host"` — and stores it with the record. This allows multi-machine querying, filtering, and conflict-free coexistence across shared remote databases.
3. **Fail-Safe Startup Fallback:**
   `SessionManager.initFromConfig` performs a non-blocking health check against the configured service. If the server is offline or unreachable, Zay logs a warning diagnostic and seamlessly falls back to the local embedded `sessions.sqlite` in the platform config directory rather than crashing the agent.
4. **Dialect Compatibility (SQLite vs. PostgreSQL):**
   The companion service (`tools/db_server/backend.py`) and migration engine (`src/session/migration.zig`) maintain dialect parity:
   - Dynamic parameter rewriting (`to_pg_sql`) converts SQLite `?` / `?1` placeholders to PostgreSQL `$1, $2, ...`.
   - `prompt_history.id` uses `bigint generated by default as identity` for PostgreSQL and `integer primary key autoincrement` for SQLite.
   - Column metadata reflection maps SQLite `PRAGMA table_info` and PostgreSQL `information_schema.columns`.
5. **Agent Database Tool Seam:**
   The `database` tool (`src/tools/database.zig`) exposes `health`, `schema`, `query`, and `exec` to the LLM agent, resolving through `ToolContext.session_backend` or the legacy `database_server_url`. Queries accept only `SELECT` statements; the legacy service path includes change counts for `exec`, while active-backend execution reports success.
6. **Direct Cloud LibSQL Backend (`turso_http`):**
   `src/db/turso.zig` implements a native LibSQL Hrana v2 pipeline client over HTTP (`POST /v2/pipeline`). It talks directly to Turso Cloud without needing an external Python daemon or local proxy:
   - **URL normalization:** Automatically normalizes `libsql://<db>.turso.io` or `https://<db>.turso.io/` to `https://<db>.turso.io/v2/pipeline`.
   - **Hrana v2 JSON parameter mapping:** Encodes values into tagged `{ "type": "...", "value": "..." }` Hrana objects (with 64-bit integers string-encoded and blobs base64-encoded).
   - **Batch execution:** Sends one Hrana `batch` request whose conditional steps run `BEGIN`, each statement, and `COMMIT` only after the previous step succeeds. A final conditional `ROLLBACK` runs whenever commit did not succeed, fulfilling `INV-DB-BATCH` in one roundtrip. Separate pipeline `execute` requests are not atomic because Hrana continues after request errors.
   - **Schema introspection:** Queries `sqlite_master` and the parameterized `pragma_table_info(?)` table-valued function through the pipeline for table definitions and column details.

7. **Direct Cloudflare D1 Backend (`d1_http`):**
   `src/db/d1.zig` implements a native Cloudflare D1 HTTP client over Cloudflare's v4 REST API (`POST .../accounts/{account_id}/d1/database/{database_id}/query`).
   - **Zero-daemon REST client:** Uses Zig's standard `std.http.Client` with bearer token auth and `std.json` serialization, requiring no Node/wrangler daemon at runtime.
   - **URL normalization:** Expands shorthand `d1://<account_id>/<database_id>` or `d1://<account_id>:<database_id>` into the canonical Cloudflare v4 REST query endpoint, appending `/query` when needed.
   - **Batch execution:** Sends batch queries using Cloudflare's public API envelope (`{"batch":[{"sql": "...", "params": [...]}, ...]`), fulfilling `INV-DB-BATCH` in a single HTTP request roundtrip.
   - **Schema introspection:** Discovers tables from `sqlite_master` (excluding SQLite and Cloudflare internal tables) and queries column metadata through the parameterized `pragma_table_info(?)` table-valued function.

8. **Shared Remote HTTP Policy:**
   `src/db/http_transport.zig` owns bearer authentication, transport-error normalization, the 30-second request deadline, and the 16 MiB response cap for all three HTTP database adapters (`remote_service`, `turso_http`, and `d1_http`). Provider modules retain URL normalization, payload serialization, status diagnostics, and response parsing. On Windows the whole exchange races a deadline because AFD handles cannot use ws2_32 socket timeouts; on POSIX send and receive socket deadlines cover both response heads and bodies. The Windows race must drain `Select.cancel()` results and free any late `.response` body — `cancelDiscard()` is invalid because the fetch task returns owned memory. Keep timeout and body-limit mechanics in this leaf rather than copying them into an adapter.

9. **Project Identity & Host-Local Cwd Binding (schema v9, 2026-09-29).**
   A roaming session belongs to a logical project; each host binds that project to its own local directories. Key files: `src/session/types.zig` (`ProjectKey`, `ProjectLocation`, `ResumeResolution`), `src/session.zig` (`create`, `resolveProjectCwd`, `bindProjectCwd`, `listByProject`, `findLatestByProject`, `initStore`), `src/tui/session_switcher.zig` (`beginResumeSelectedSession`, `confirmProjectRootBinding`), `src/paths.zig::cwdKey`.
   - **INV-PROJECT-ID:** `sessions.project_key` is an opaque `pk-<32 hex>` identity minted by the private `SessionManager.mintProjectKey` buffer helper (`session.zig`) and validated by `ProjectKey.validate` — never a path, never a Git remote URL. The lane manifest's `repo_key` keeps its local-path semantics; the two are never interchanged.
   - **INV-RESUME-CWD:** a foreign or missing `sessions.cwd` is NEVER executed as a runtime root. `resolveProjectCwd` returns `ResumeResolution` — `.ready` (a verified current-host root: the bound current root, else the newest existing current-host location) or `.needs_project_root` (the TUI asks). `switchToSessionResolved` is the only low-level resume boundary and requires an already-resolved root.
   - **INV-HOST-BINDING:** `project_locations` is host-scoped with PK `(project_key, host_id, cwd_key)`; `cwd_key` is the persistent normalized spelling from `paths.cwdKey` (separator-run collapse, trailing-separator drop, ASCII case-fold on Windows — matching `pathsEqual`). Application-level path comparisons use `paths.pathsEqual`, never byte `eql` (the cross-project detection in `createRuntimeImpl` was converted).
   - **INV-LEGACY:** `project_key = NULL` stays representable. Migration NEVER backfills from old cwd values (old remote rows carry `default-host` from several machines — a SQL-only backfill could merge unrelated projects). A same-host legacy row with an existing cwd is lazily bound at resolve time; foreign/missing rows ask for a project root, and a successful bind stamps only that row.
   - **INV-BACKEND:** picker list/rename/delete/bind/resume all open the store through `SessionManager.initStore` (or `SessionWriter.initFromStore`/`initResumeFromStore`) with the config-derived `SessionStore` — never `initDefault`. Resume passes `fallback_ok = false`: an unreachable remote store fails loudly instead of silently resolving the id against local SQLite (a misleading `MissingSession`). New-session creation keeps `fallback_ok = true` (startup fail-safe).
   - **INV-HOST-ID:** the host id is resolved ONCE at the process boundary (`root.run` via `session.resolveHostId`, honoring `ZAY_HOST_ID` → `COMPUTERNAME` → `HOSTNAME`) and carried through `AgentRuntime.Genesis.host_id` into every new/resumed/lane runtime. The old `env_map = null` path recorded `"default-host"` on every machine.
   - **INV-TUI-BIND:** the `.locating_project` picker sub-state validates (absolute, existing, readable, realpath-canonicalized) BEFORE any mutation; cancel (Esc) and invalid input perform no config/plugin/MCP/runtime/session mutation. `App.pending_resume` owns a `PendingProjectBinding` copy — never a `SessionSummary*` (a reload frees it via `resumeClear`).
   - Startup auto-resume order (root.zig): validated driver pin → `findLatestByProject` ONLY when the launch root already has a binding → legacy `findLatest` cwd filter. Startup stays non-interactive; an unbound root starts a new session.
   - Resume grouping sorts by `groupKeyOf` (`project_key` when bound, else origin cwd) so project-mode folds roaming sessions of one project across hosts; a bound project with no local mapping shows "project root required" and its origin host in the picker.

The session serializer maps OOM to `error.WriteFailed` (not `error.OutOfMemory`); tests must expect that. See the queue admission and failure policy above.
